# Payload shapes where the vendored Vulkan engine's reader does not agree with this host's writer
#
# Scope: only ops both sides implement (the 12 with no handler at all are rows in opcode_map.txt, not
# mismatches). dm/gfx/nvn/hle_nvn.c is the writer and the ground truth: it is what 93 game profiles
# record through, and its records are sized by what games measure with GetCommandMemoryUsed. The engine
# (dm/gfx/vulkan/engine/xbg_game.cpp) is read here as compiled against dm/gfx/nvn/nvn_obj.h - that is
# what this sprint made possible - so the *byte offsets* it uses are this header's offsets. What differs
# is the record length a writer emits, which fields the reader consumes, and the rules it applies to
# them.
#
# Ids match the payload column of opcode_map.txt; opcode_map.py --check fails when the two lists differ
# and when a size quoted below no longer matches a probe compiled against nvn_obj.h. Measured today
# (clang++ 21, x86_64; sizeof never depends on the target here, every struct is fixed-width):
#   sizeof(p_draw)=48  offsetof(p_draw, ind)=24
#   sizeof(p_draw_idx)=56  offsetof(p_draw_idx, ibuf)=24  offsetof(p_draw_idx, ind)=32
#   sizeof(p_dispatch)=32  sizeof(p_bind_handles)=280  offsetof(p_bind_handles, h)=24
#   sizeof(p_bind_tex1)=24  sizeof(p_copy_stride)=16  sizeof(p_bind_ubo_small)=16
#   sizeof(p_bind_vbuf1)=16  sizeof(p_viewports)=392  sizeof(tex_t)=128

== P8 OP_BARRIER (28): the cache bits are ignored (benign)
writer:  hle_nvn.c:1047 records NVN's int bits (which caches the barrier orders).
reader:  xbg_game.cpp:3815 records one full VkMemoryBarrier regardless, which is stronger, so nothing
         is drawn wrong. What is lost is the Metal replay's use of the bits: a game barrier after
         shader writes ends the pass there (nvn_mtl.m:10041) and the barrier marks the ordering point
         for the next draw pass.
right:   the writer, but the reader is conservative enough to be correct.
fix:     nothing for correctness; if passes are to be merged as nvn_mtl.m merges them, the bits are
         needed to know where a pass may not be merged.

# Fixed, recorded in opcode_map.txt's note column: P1-P5, P7 (the first sprint) and P6 (OP_VIEWPORTS, in the
# draw: the handler writes viewport[first..first+n) and keeps the array's length; the draw declares that many
# viewports as dynamic state, with the one recorded scissor and depth range for each, only when the last
# pre-raster shader writes ViewportIndex, and one otherwise, which keeps nvn_cover's one-viewport proof for
# every non-selecting draw; multiViewport / maxViewports / the enabled shaderOutputViewportIndex are checked
# and validate_capabilities accepts the viewport capabilities; a viewport mask (ViewportMaskNV) is refused
# with a [RED] line). Still unreachable end to end: the front end does not enable shaderOutputViewportIndex,
# the writer collapses SetScissors / SetDepthRanges to index 0, the multiview fan-out is open; see
# docs/reference/android.md, "The replay refused a record of more than one viewport".
#
# Not mismatches, checked and left alone:
#  - Texture-carrying records (OP_SET_RT, OP_COPY_B2T / T2B, OP_COPY_T2T, OP_CLEAR_TEX) carry a tex_t
#    snapshot after the struct (hle_nvn.c REC_SNAP, SNAP_OFF). The engine reads payload<...> of the
#    struct alone and then follows the pointers, which point into that same record, so the snapshot is
#    always there and always alive: no change needed.
#  - p_bind_handles at offset 24: this README's earlier note that the engine reads h at 16 was measured
#    against the fork's header. Compiled against this header (which it now is) offsetof(h) = 24 is
#    right; the live defect in that op is P4 and the ignored defer/src (a BindTexturesDeferred handle is
#    then the recording-time value, usually 0 - fixed on Metal by bh_fresh, missing here).
#  - OP_BIND_IMG: image slots 0..15 fit the engine's uint64_t img[6][16].
#  - OP_BIND_UBO / OP_BIND_SSBO / OP_BIND_VATTR / OP_BIND_VSTREAM / OP_BIND_VBUF: our writer emits
#    variable-length records and the engine reads them with variable_payload and an explicit n check.
